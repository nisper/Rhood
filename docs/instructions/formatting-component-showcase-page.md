# Оформление страницы витрины компонента

## Назначение

Используй эту инструкцию при создании или переработке страницы компонента в «Витрине компонентов».

## Базовый паттерн

- Ориентируйся на `src/components/prototype/button-examples.tsx` как на эталон структуры и визуального ритма.
- Подключай страницу через `src/components/prototype/component-docs.tsx`.
- Используй `ShowcaseSection` для секций с примером: он объединяет заголовок, описание и Showcase. Внутри него используй `ShowcaseSurface`, `ShowcasePanel`, `Table` и `TableCell` по существующему паттерну.
- Сохраняй порядок секций:
  1. Стиль
  2. Размер
  3. Состояния
  4. Состав
  5. Свойства

Не создавай пустые секции: если компонент не поддерживает соответствующее свойство, пропусти секцию и объясни это в описании ближайшей релевантной секции.

## Содержимое секций

- «Стиль» — все поддерживаемые `appearance` или визуальные варианты.
- «Размер» — по одному исходному, неактивному примеру каждого размера. Для интерактивного компонента пользователь должен сам иметь возможность переключить его.
- «Состояния» — `default`, `hover` и `disabled`, если они поддерживаются. Используй статичный prop состояния только для демонстрации; нативный hover обязан работать при наведении.
- «Состав» — иконки, подписи, счётчики, icon-only и другие составные части, а также реальное интерактивное поведение компонента.
- «Свойства» — таблица со столбцами «Свойство», «Значения», «По умолчанию», «Назначение». Добавляй только публичные и действительно поддерживаемые props.

## Стили и реализация

- Используй компоненты и дизайн-токены RHOOD; не добавляй новые цвета, размеры, радиусы или типографику, когда есть подходящий токен.
- Tailwind используй только для компоновки или если в RHOOD нет подходящего решения.
- Не меняй production API компонента ради витрины.
- Если компонент интерактивный, демонстрационные экземпляры должны быть кликабельны и отражать реальное поведение.
- Добавь ссылку на Figma и исходный файл компонента в запись `componentDocs`, если они известны.

## Проверка

- Запусти lint для изменённых файлов.
- Запусти `git diff --check`.
