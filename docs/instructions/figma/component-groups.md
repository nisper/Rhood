# Component Groups

Этот файл описывает не отдельные компоненты, а группы компонентов и правила выбора:

- кнопки и действия;
- поля и form controls;
- навигация;
- таблицы и списки;
- статусы и бейджи;
- feedback-компоненты;
- overlays;
- контейнеры и карточки.

Подробно описывай только различия, ограничения, устаревшие компоненты и ситуации, где легко выбрать неправильный компонент.

## Базовое Правило

- Собирай макеты только из существующих компонентов в подключенной библиотеке.
- Перед созданием нового элемента сначала проверь, нет ли подходящего компонента, варианта или допустимой комбинации уже существующих библиотечных компонентов.
- Если подходящего компонента в библиотеке нет, не придумывай новый молча: сначала обсуди это с пользователем.
- Не маскируй новый паттерн под "небольшую правку", если по сути это новый компонент или новая компонентная логика.

## Работа С Компонентами В Концептах

- Если делаешь копию экрана для своего концепта, detach только те компоненты, которые действительно собираешься править.
- Остальные компоненты на экране оставляй нетронутыми.ы
- Не меняй состав, порядок, внешний вид, варианты, иконки и подписи существующих кнопок, табов, фильтров, меню и других контролов без явной задачи от пользователя.
- Если работа не касается этих контролов напрямую, переноси их из исходного макета без изменений.

## Styles И Semantic Tokens

- Для текста используй существующие text styles из подключенной библиотеки.
- Для цветов, поверхностей, border, radius и spacing используй semantic tokens/variables  из подключенной библиотеки.
- Не задавай локальные визуальные значения вручную. Сначала используй подходящий системный стиль или token из подключенной библиотеки. Если подходящего стиля или token нет, не придумывай новое значениеы молча: зафиксируй вопрос пользователю.
- Не оставляй новый текст на вручную заданных `font size`, `line height`, `letter spacing` и `fill`, если для него есть подходящий системный стиль.
- Не подставляй цвет вручную, если в файле существует подходящий semantic token.
- Если подходящего текстового стиля или semantic token нет, сначала обсуди это с пользователем.
