# Набор базы объектов

## Краткое описание

Сценарий описывает, как СПН открывает выдачу новых объектов, выбирает объект для звонка, связывается с собственником и фиксирует результат разговора. Если собственник готов работать с "Этажами", объект сохраняется в CRM, и дальше запускается бизнес-процесс продажи.

## Пользователь

- Роль: СПН.
- Рабочая задача: быстро прозвонить новые объекты и взять в работу те, где собственник готов работать с "Этажами".
- Мотивация: быстрее пополнять базу объектов и не тратить время на лишние действия вокруг одного и того же объекта.
- Частота использования: регулярно, во время обработки выдачи по набору базы.
- Контекст работы: утренний или регулярный разбор свежей выдачи с быстрым переходом к звонкам.
- Что пользователь уже знает: базовые параметры объекта, источники объявлений, смысл статусов контакта и дальнейший процесс сохранения объекта в CRM.
- Основные боли: много новых объявлений, риск повторной работы по одному объекту, потеря времени на ручную фиксацию результата.

## Цель пользователя

Быстро разобрать свежую выдачу, прозвонить новые объекты и перевести перспективные объекты в дальнейшую работу через CRM.

## Предусловия

- Пользователь авторизован в RHOOD.
- Город пользователя подключен к набору базы.
- Для городского контура есть найденные уникальные объекты.
- Выдача содержит данные, достаточные для первичной оценки объекта и перехода к звонку.

## Основной путь

1. Пользователь открывает раздел `Набор базы`.
2. Система показывает список новых объектов по доступному городскому контуру.
3. Пользователь просматривает свежую выдачу и выбирает объекты по которым хочет позвонить.
4. Пользователь нажимает `Позвонить` в строке выдачи, в drawer с подробной информацией об объекте или на странице объекта.
5. Пользователь связывается с собственником, представляется и предлагает работать с "Этажами".
6. Если собственник соглашается, пользователь нажимает `Сохранить в CRM` в drawer или на странице объекта.
7. Система создает объект и заявку на продажу в CRM `Космос`, запускается дальнейший бизнес-процесс продажи.
8. Если собственник не готов работать с "Этажами", пользователь завершает разговор и фиксирует соответствующий статус в RHOOD.

## Альтернативные пути

- Если собственник просит связаться позже или не принимает решение сразу, пользователь завершает разговор и ставит статус вроде `Думает`.
- Если собственник уже работает с другим агентством, пользователь ставит статус `Другое АН`.
- Если собственник отказывается работать с "Этажами", пользователь ставит статус `Отказ`.
- Если уникальные объекты не найдены, пользователь видит пустое состояние и может изменить фильтры или вернуться позже.
- Если город не подключен, система сообщает, что в этом городе парсер ничего не ищет.

## Состояния и ошибки

- Пустое состояние: уникальные объекты не найдены или фильтры слишком ограничили выборку.
- Загрузка: система получает или обновляет выдачу.
- Успешное состояние: пользователь видит список объектов, готовых к обработке.
- Ошибка: данные не удалось загрузить или часть источников временно недоступна.
- Недоступно или отключено: город пользователя не подключен или парсинг временно отключен.

## Точки принятия решений

- Пользователь решает, какие фильтры помогают быстрее найти приоритетные объекты.
- Пользователь решает, какой объект прозвонить следующим.
- Пользователь решает, готов ли собственник работать с "Этажами".
- Пользователь решает, какой статус разговора поставить по итогам контакта.

## Связанный интерфейс

- Экраны: `Набор базы`, список объектов.
- Компоненты: таблица объектов, фильтры, drawer объекта, кнопка `Позвонить`, кнопка `Сохранить в CRM`, статусы обработки.
- Дизайн-референсы: будут добавлены после фиксации актуального макета.

## Связанные данные

- Сущности: уникальный объект, объявление, группа объявлений, источник, статус обработки, городской контур, CRM `Космос`.
- Входные данные: список новых объектов, параметры фильтров, доступные города, данные для звонка и признаки связанных объявлений.
- Выходные данные: зафиксированный результат звонка, обновленный статус объекта, созданный объект и заявка в CRM при успешном согласии.

## Критерии успешности

- Пользователь видит только объекты из доступного городского контура.
- Пользователь может быстро перейти от свежей выдачи к звонку по объекту.
- Пользователь понимает, какие объекты уже были обработаны и какой у них текущий статус.
- Пользователь может без лишних шагов сохранить согласившийся объект в CRM.
