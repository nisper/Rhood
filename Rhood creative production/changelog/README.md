# Changelog

Здесь фиксируем важные изменения в продукте, Figma-системе, документации и рабочих договорённостях.

Это не список всех правок. В changelog попадает только то, что поможет потом понять, почему проект изменился и где это может отразиться.

## Когда делать запись

Добавляй запись, если изменились:

- Component set, variants, component properties, variables, styles или modes в Figma;
- правила использования компонентов;
- продуктовая логика, сценарии или карта фич;
- названия сущностей, термины или важные copy-договорённости;
- структура документации или рабочий процесс;
- решение, которое может повлиять на будущие макеты, тексты или разработку.

Не нужно фиксировать:

- мелкие правки формулировок без изменения смысла;
- техническую уборку без влияния на продуктовые решения;
- временные черновики и эксперименты, если по ним не принято решение.

## Формат

Один файл на день:

```text
changelog/YYYY-MM-DD.md
```

Внутри дня группируй изменения по темам:

```markdown
# YYYY-MM-DD

## Название темы

Ссылка на источник, если есть: Figma, документ, задача.

### Что изменилось

- Коротко описать изменение.

### Почему

- Зафиксировать причину или принятое решение.

### Где может отразиться

- Указать связанные component sets, instances, документы, сценарии или открытые вопросы.
```

## Правило записи

Пиши коротко и по делу: изменение, причина, последствия.

Если причина неизвестна, так и фиксируй: `Причина не зафиксирована`.

Если есть риск, что изменение затронет другие места, лучше записать это как открытый вопрос, чем промолчать.
