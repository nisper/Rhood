# Layout и композиция

Этот документ хранит правила, по которым собираются экраны RHOOD. Здесь фиксируем только проверенные решения; вопросы и гипотезы держим отдельно.

## Поверхности для контента

Контент в RHOOD размещается на двух типах поверхностей:

1. Основной контейнер экрана;
2. Модальные контейнеры — instances компонентов `Modal` и `Drawer`.

### Основной экран

Может быть два режима работы

#### Edge-to-edge
Когда надо прижать контент на мобильных устройствах к краям экрана.

Если структура основного контейнера сохраняется на всех ширинах, он использует связанную пару variables:

```text
View Port
└── wrapper — боковые padding: `layout/edge-to-edge/wrapper`
    └── content — боковые padding: `layout/edge-to-edge/content`
        └── Контент
```

- **На desktop** отступы задаются переменной `layout/edge-to-edge/wrapper` 
- **На Mobile*** отступы задаются переменной `layout/edge-to-edge/content`

Если mobile использует отдельный variant компонента, эта пара не обязательна. Variant переключается через `component property`, связанную с `resp/resp`; layout variables внутри variant всё равно используем, чтобы изменения их значений применялись ко всем связанным компонентам.

####  У контейнера просто меняется отступ на мобилке

`Modal`, `Drawer` и похожие поверхности используют один token `layout/container`. Он делает размер отступов на мобилке поменьше.

## Базовые правила

### `layout/edge-to-edge/wrapper`

- Применяется к внешней обёртке основного контейнера;
- Используется и в отдельных responsive variants, если их содержимое должно быть связано с общими внешними отступами.

### `layout/edge-to-edge/content`

- Применяется к вложенному контейнеру, а не ко всему контенту основного экрана;
- В паре с `layout/edge-to-edge/wrapper` возвращает боковые поля для mobile в неизменной структуре.

### `layout/container`

- Применяется к контенту самостоятельных контейнеров: `Modal`, `Drawer` и похожих поверхностей;
- Не требует парной обёртки.

### Ограничение ширины

- Основной контейнер по умолчанию не ограничен по ширине;
- На страницах личного кабинета ширину внутренней колонки ограничивает `layout/column-container-md`;
- Этот token применяется внутри основного layout и не заменяет его outer padding.

### Переполнение по ширине

- Контент по умолчанию остаётся в границах основного контейнера;
- Если блоку нужна минимальная ширина больше доступной — например, таблице, — он получает локальный горизонтальный scroll;
- Переполнение блока не меняет padding и ширину основного контейнера.

## Правило близости

- Внутренний gap элементов одной группы по умолчанию меньше внешнего gap между группами;
- Так отступы передают структуру: близкие элементы считываются как единый блок;
- Если между группами нужен внешний gap, помещай их в соседние контейнеры внутри общего Auto Layout и задавай gap у него;
- Не добавляй внешний блок в контейнер, который задаёт внутренний ритм повторяющихся элементов;
- Отступаем от правила только осознанно, когда это нужно для композиции конкретного экрана.
