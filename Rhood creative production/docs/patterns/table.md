# Data table

Паттерн для показа и обработки набора однотипных записей в строках и колонках. Он описывает общую структуру таблицы, а не данные конкретной фичи.

## Основное правило

- Для таблиц используй instance `table` из библиотеки `Parser – Components` по [source.figma_url](https://www.figma.com/design/MbjYVdGZqH95blipWMHXtp/Parser-%E2%80%93%C2%A0Components?node-id=416-3328&t=aJkr9gtOs2GuxbYT-11).
- Detach instance `table`, чтобы настроить состав колонок и количество строк под конкретную фичу.
- Наполняй вложенные `head row` и `cell row` нужным количеством instances `table-cell`; дублируй подготовленную `cell row` для строк данных.
- Не пересобирай вручную auto layout, borders, padding и bindings Figma variables: они наследуются от `table` после detach.
- В `head row` используй `table-cell` с `role=head`, в `cell row` — с `role=body`.
- Для числовых значений используй `type=number`.
- Меняй только содержимое slots, variants, component properties и нужные overrides instances `table-cell`; не detach их и не заменяй ручными ячейками.

## Когда использовать

- Нужно сравнить несколько записей по общим параметрам;
- Пользователь обрабатывает записи построчно;
- Важны быстрые действия или выбор нескольких записей.

## Когда не использовать

- Нужно изучить одну запись подробно — используй карточку, drawer или отдельную страницу;
- Данные не требуют сравнения по колонкам;
- Основная задача — пространственный анализ данных на карте.

## Состав

| Часть             | Роль                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| Контейнер таблицы | Содержит заголовок и строки таблицы. При нехватке ширины даёт локальную горизонтальную прокрутку.         |
| Строка заголовков | Объясняет состав и смысл колонок.                                                                         |
| Строка данных     | Показывает одну запись.                                                                                   |
| Колонка выбора    | Опционально позволяет выбрать одну или несколько записей.                                                 |
| Колонка действий  | Опционально даёт доступ к действиям в контексте записи.                                                   |

## Структура

```text
table (после detach)
├── head row
│   ├── Ячейка выбора (опционально)
│   ├── Ячейки заголовков данных
│   └── Ячейка действий (опционально)
└── cell row
    ├── Ячейка выбора (опционально)
    ├── Ячейки данных
    └── Ячейка действий (опционально)
```

- `head row` — единственная строка заголовков;
- `cell row` — строка одной записи: дублируй её для нужного количества записей;
- Добавляй или удаляй instances `table-cell` внутри `head row` и `cell row`, чтобы задать состав колонок;
- Состав и порядок колонок определяет конкретная фича;
- Не добавляй колонку, если она не помогает сравнить записи или выполнить рабочее действие.

## Строки

- Ширина строки — `fill` по ширине таблицы, высота — `hug`;
- Не задавай фиксированную высоту ячейкам и строкам, если я явно тебе этого не скажу;
- Не создавай отдельные горизонтальные `line`, `rectangle` или `divider` между строками и не добавляй их в `table-cell`: в контейнере таблицы между строками не должно быть самостоятельных слоёв-разделителей;
- Перед сдачей проверь структуру контейнера: его прямые дочерние элементы — только строки таблицы, без отдельных слоёв-разделителей;
- Высоту строки задаёт самая высокая ячейка.

## Ячейки

| Содержание                         | Компонент и настройка                                                              |
| ---------------------------------- | ---------------------------------------------------------------------------------- |
| Обычный текст                      | `table-cell`, `role=body`, `type=text`                                             |
| Число                              | `table-cell`, `role=body`, `type=number`: моноширинный текст и выравнивание вправо |
| Двухстрочный или составной контент | `table-cell`, `role=body`: добавь нужные layers или instances в slot `slot`        |
| Выбор строки                       | `table-cell`, `role=body`, `type=checkbox`                                         |
| Загрузка данных                    | `table-cell`, `role=body`, `type=skeleton`                                         |
| Обычный заголовок                  | `table-cell`, `role=head`, `type=text`                                             |
| Числовой заголовок                 | `table-cell`, `role=head`, `type=number`                                           |
| Выбор всех строк                   | `table-cell`, `role=head`, `type=checkbox`                                         |
| Загрузка заголовка                 | `table-cell`, `role=head`, `type=skeleton`                                         |

- В `type=text` и `type=number` добавляй содержимое ячейки или заголовка в slot `slot`.
- `paddingX=false` используй только когда горизонтальные отступы задаёт родитель.
- Значение `sizeSmall` должно совпадать у всех ячеек одной таблицы.

## Данные и форматирование

- Формат чисел, дат и времени определяет конкретная фича;
- Выравнивание значений одного типа должно быть консистентным в пределах колонки;
- Пустые ячейки не заменяй прочерком.

## Сортировка

- Для сортируемого заголовка используй `table-cell` с `role=head`, `type=text` или `type=number` и `sort=true`;
- Вся сортируемая ячейка заголовка кликабельна;
- При наведении в правом верхнем углу ячейки появляется стрелка: она показывает, что по нажатию включится сортировка A–Z;
- При нажатии применяется сортировка, а стрелка остаётся в правом верхнем углу, пока таблица отсортирована по этому параметру;
- Повторное нажатие на ячейку с включённой сортировкой меняет её направление.

### Настройки конкретной фичи

- В документации фичи фиксируй начальный параметр и направление сортировки конкретного списка;
- Не повторяй там общее поведение клика и стрелки: оно описано в этом паттерне.

## Layout и responsive-поведение

- Таблица остаётся в границах основного контейнера экрана;
- Если минимальная ширина таблицы больше доступной, не меняй padding основного контейнера и не сжимай содержание до нечитаемого состояния: используй локальную горизонтальную прокрутку таблицы;
- Состав колонок и их поведение на tablet и mobile определяет конкретная фича.
