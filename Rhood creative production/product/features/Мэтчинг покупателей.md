# Мэтчинг покупателей

## Краткое описание

Фича проверяет каждый объект из парсера на наличие подходящих покупателей в базе "Этажей". Если совпадение найдено, система показывает специальный индикатор в выдаче и в карточке объекта. Фича помогает быстрее выделять объекты с потенциально более коротким путем до сделки.

## Польза для пользователя

СПН может сразу увидеть, есть ли в базе "Этажей" потенциальный покупатель на найденный объект, чтобы быстрее приоритизировать разбор выдачи и звонки по самым перспективным вариантам.

## Ограничения

- Rhood не может постоянно опрашивать космос (в данном случае, база Этаже) на предмет подходящих потребностей, космос ляжет;
- Rhood спрашивает космос о подходящей потребности 2 раза:
	- Когда объект появляется в парсере;
	- Через 2 часа после появления объекта в парсере.
- Данные по подходящей потребности актуализируются пользователем в дровере или на странице объекта по кнопке.

## Проверка на наличие покупателей

- Подходящий покупатель в базе "Этажей" - это заявка на покупку, в которой заполнена потребность клиента.
- Мэтчинг происходит, если объект из парсера соответствует потребности, указанной в такой заявке.
- Проверка запускается автоматически, когда объект впервые попадает в выдачу парсера.
- Через 2 часа после появления объекта в выдаче система автоматически запускает повторную проверку.
- Пользователь может вручную отправить запрос на проверку наличия подходящих покупателей для конкретного объекта.
- Автоматические и ручные проверки работают в фоне.

## Поведение

- Когда новый объект попадает в выдачу парсера, система автоматически запускает проверку на наличие подходящих покупателей в базе "Этажей".
- Результатом проверки является бинарный признак: совпадение есть или совпадения нет.
- Если совпадение найдено, в строке объекта в выдаче показывается специальный индикатор наличия покупателя.
- Тот же самый признак должен показываться в карточке объекта, чтобы состояние было консистентным между уровнями интерфейса.
- Если совпадение не найдено, индикатор не показывается.
- Фича не показывает количество покупателей и не раскрывает список заявок внутри выдачи или карточки объекта.
- Если данные мэтчинга обновились, новое состояние должно одинаково отразиться и в выдаче, и в карточке объекта.

## Состояния

- Пустое состояние: у объекта нет совпадений с покупателями, индикатор не показывается.
- Загрузка: объект появился в выдаче, система еще не завершила автоматическую проверку мэтчинга.
- Успешное состояние: проверка завершена, и система показывает актуальный бинарный признак наличия или отсутствия совпадения.
- Ошибка: проверку не удалось выполнить или не удалось получить результат из базы покупателей.
- Недоступно или отключено: источник данных покупателей временно недоступен или функция выключена для текущего контура.

## Крайние случаи

- У объекта могут быть подходящие покупатели, но их состав и количество меняются чаще, чем обновляется выдача.
- Объект отображается в нескольких представлениях интерфейса, и индикатор должен оставаться консистентным в каждом из них.

## Связанный интерфейс

- Экраны: `Набор базы`, карточка объекта.
- Компоненты: строка объекта в таблице, колонка `Покупатель`, карточка объекта, индикатор наличия покупателя.
- Спецификация интерфейсов выдачи: [Режимы выдачи объектов](<Режимы выдачи объектов.md>).

## Связанные данные

- Сущности: объект из парсера, заявка на покупку, потребность клиента, признак мэтчинга.
- Входные данные: объект парсера, база покупателей "Этажей", правила сопоставления.
- Выходные данные: бинарный признак наличия совпадения для выдачи и карточки объекта.

## Открытые вопросы

- Нужен ли пользователю отдельный фильтр по объектам с найденным покупателем?
- Нужно ли где-то вне выдачи и карточки раскрывать источник совпадения, например конкретную заявку или сегмент покупателя?
