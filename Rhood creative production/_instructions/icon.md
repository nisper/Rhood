# Icon Instructions

Этот файл хранит отдельные рабочие правила по иконкам в Figma для проекта RHOOD.

Сюда складываем не общие принципы UI, а конкретные договоренности про поиск, замену и актуализацию иконок.

## Где лежит актуальный набор

- Если задача сформулирована как `подбери иконку из имеющегося набора`, сначала всегда искать иконку в файле `Parser – Lucide icons`: `https://www.figma.com/design/KnDZk2yHoZmGJhJMpASfFo/Parser-%E2%80%93%C2%A0Lucide-icons?node-id=0-1&p=f&t=VG4NyjBTR1R9blV1-11`, а не в текущем макете.

## Базовые правила

- После выбора иконки нужно зафиксировать ее точное название или компонент.
- Затем иконку нужно добавлять в рабочий макет через библиотеку, инстанс, instance swap или другой чистый способ переиспользования.
- Не подбирать иконки по случайным инстансам из текущего экрана, если пользователь явно просит выбрать из существующего набора.
- Не создавать новые локальные иконки, новые локальные мастера иконок или свои промежуточные версии иконок, если пользователь явно этого не просил.
- Использовать только существующие иконки из источника, зафиксированного в этой инструкции.
- Если при выборе иконки есть сомнение, например подходят несколько кандидатов, не выбирать самостоятельно.
- В такой ситуации нужно перечислить пользователю кандидатов и попросить его указать, какую иконку использовать.
- В таких случаях нужно перечислять пользователю именно названия иконок-кандидатов.
- Не перечислять кандидатов как набор `node-id` без нормальных названий.
- Если полезно для различения, можно дополнительно указать категорию или секцию, где лежит иконка, но основным идентификатором в ответе должно быть название иконки.
- Если пользователь просит `актуализировать иконки`, это означает, что в компоненте сейчас используются старые иконки, не из правильной библиотеки, или мастера этих иконок не существуют.
- В таком случае нужно заменить иконки в тех компонентах, о которых идет речь, на правильные существующие компоненты согласно этой инструкции.
- Перед заменой нужно проверять источник `main component` у иконки.
- Если иконка приходит из файла `Parser – Icons`, ее нужно считать кандидатом на актуализацию.
- Если иконка уже приходит из файла `Parser – Lucide icons`, по умолчанию ее можно пропустить и не заменять повторно.
- Если пользователь просит актуализировать иконки в конкретном узле, нужно обновлять все иконки внутри этого узла, включая `nested instances`, если они участвуют в текущем отображении или состоянии узла.
- Если вложенная иконка скрыта или находится внутри другого компонента и не влияет на результат в целевом узле, обновлять ее не нужно.
- По умолчанию нужно менять только те иконки, которые реально относятся к запросу пользователя и проявляются в целевом результате.

## Машиночитаемая пометка иконок

- Для явной пометки иконок в компонентах используем формат имени `ic icon_name`.
- Примеры: `ic help`, `ic info`, `ic thumbs-up`, `ic circle-question-mark`.
- Префикс должен быть именно `ic ` с пробелом.
- Если в имени объекта есть префикс `ic `, такой объект нужно считать целевой иконкой для поиска, проверки и актуализации.
- При разборе компонента отдельно сообщай, если прямой nested instance иконки не имеет префикса `ic `.
- При актуализации иконок сначала нужно искать в релевантном компоненте объекты с префиксом `ic ` и работать в первую очередь с ними.
- Имя после `ic ` нужно использовать как основной ключ для поиска подходящей иконки в правильном источнике.
