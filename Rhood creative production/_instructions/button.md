# Button Instructions

Этот файл хранит рабочие правила актуализации кнопок в Figma для проекта RHOOD.

## Перед началом

- Для свойств и допустимых `variants` текстовой кнопки читать [buttons.md](../docs/components/buttons.md).
- Для свойств и допустимых `variants` кнопки только с иконкой читать [icon-buttons.md](../docs/components/icon-buttons.md).
- При актуализации иконок также читать [icon.md](icon.md).

## Работа с кнопками

- Для нового действия сначала искать подходящий инстанс в текущем файле или библиотеке.
- Если подходит существующий инстанс, использовать его.
- Никогда не создавать новую кнопку с нуля.
- Если подходящего компонента нет или выбор компонента, `variant` либо свойства неоднозначны, остановиться и уточнить у пользователя.
- При переиспользовании библиотечного компонента не добавлять визуальные эффекты или декоративные отличия без явного запроса.
- Если компонент не подходит в исходном виде, спроси пользователя.

## Актуализация текстовых кнопок

- Единственный актуальный текстовый компонент — [button](https://www.figma.com/design/MbjYVdGZqH95blipWMHXtp/Parser-%E2%80%93%C2%A0Components?node-id=10647-1326).
- Все остальные текстовые компоненты кнопок считаются legacy.
- При актуализации заменять legacy-кнопку на `button`, только если подходящий `variant` определяется однозначно.
- При замене сохранять смысл действия, `style`, `size`, `state`, `disabled`, label, а также видимость `startIcon`, `endIcon` и `counter`.
- Если подходящий `variant` определить нельзя, остановиться и уточнить у пользователя.

## Кнопки только с иконкой

- Если у legacy-кнопки нет label и включено свойство вроде `hasIconOnly=true`, заменять её на `icon button`.
- При замене сохранять `style`, `size`, `state` и иконку через instance swap.
- Если специализированная кнопка содержит свойство или состояние, которого нет у `icon button` — например, `checked`, — не заменять её автоматически. Актуализировать только вложенную иконку и уточнить дальнейшую миграцию при необходимости.
