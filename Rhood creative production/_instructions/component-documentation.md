# Документация компонентов

## Где хранить

Документацию компонентов храним в папке `docs/components` одним Markdown-файлом. Имя файла записываем в kebab-case: строчными буквами, заменяя пробелы дефисами.

- `docs/components/input-date.md`.

Имя компонента в Figma, в JSON и в тексте документа не нормализируем: сохраняем пробелы, регистр и другие символы из Figma.

## Что хранить

Первый блок в `.md` — валидный JSON с точной структурой компонента из Figma: ссылкой на component set, variant properties, component properties, допустимыми значениями и значениями по умолчанию.

После JSON держим читаемую документацию: таблицы, объяснения и принятые договорённости.

Имена `variant properties` и `component properties` воспроизводим из Figma без нормализации: сохраняем регистр, дефисы и пробелы. То же имя используй в таблицах, примерах и `usage_rules`, если правило описывает конкретное свойство. Не заменяй имя свойства на snake_case или другой удобный alias. Служебные ключи `usage_rules`, которые не описывают конкретное свойство, могут быть смысловыми.

## Связи компонентов

- Первую таблицу после JSON называем `Сводка компонента`: в ней фиксируем только собственные свойства компонента;
- Если компонент использует другой компонент или открывает его, добавляем таблицу `Использует компоненты` с его ролью;
- В JSON те же связи фиксируем в массиве `dependencies`: `component`, `documentation`, `relation` и `role`;
- `documentation` оставляем пустым, если документация зависимого компонента ещё не создана.

## Как обновлять

- При изменении component set сначала обновляй JSON-блок.
- Затем приводи читаемую часть `.md` в соответствие с JSON.
- После создания документа компонента ищи его упоминания в `docs/components`. Если компонент уже указан в `dependencies` или таблице `Использует компоненты`, добавь ссылку на новый `.md` и заполни поле `documentation` в JSON.
- Когда пользователь даёт компонент для анализа или добавления в документацию, всегда проверяй, не упоминается ли он в других файлах `docs/components`. Если упоминается, обновляй эти места ссылкой на новый `.md` и полем `documentation` в JSON.
- Не добавляй в JSON догадки: только зафиксированные свойства и решения.
- Если решение ещё не принято, выноси его в открытый вопрос в `.md`.
- Не добавляй статусы компонентов или документации в JSON и читаемую часть `.md`.
