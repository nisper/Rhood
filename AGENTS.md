# Инструкции по проекту

## Базовые правила

- Это high-fidelity прототип, а не production.
- В ссылках на документацию указывай файл и нужную секцию. Номер строки можно добавить для ориентира.
- Обращайся к пользователю на "ты".
- Отвечай коротко: сначала главный вывод, потом 3–5 пунктов максимум. Без длинных объяснений, если пользователь не просит.
- Не пиши финальный текст инструкции целиком, пока пользователь не попросит. Сначала предлагай структуру и 2–3 ключевых правила.


## Работа с текстом

- Диапазоны, интервалы и иные промежутки отделяй знаком `–`. Единицу измерения указывай в конце диапазона: `10–20 ₽`, `5–7 дней`. Примеры: `май–июнь`, `стр. 5–7`.
- Суммы меньше 1 млн ₽ показывай полностью, разделяя тысячи пробелами: `250 000 ₽`. Суммы от 1 млн ₽ сокращай до `млн ₽`: `1,2 млн ₽`.

## UI и дизайн-система

- Перед созданием нового UI используй существующие компоненты из `src/components/ui` и токены из `src/styles/design-tokens.css` как источник стилей дизайн-системы RHOOD.
- Используй токены и компоненты RHOOD для стилей, цветов, размеров и радиусов. Применяй Tailwind для компоновки и только там, где в RHOOD нет подходящего решения. Не добавляй через Tailwind значения, для которых уже есть токен или компонент RHOOD.
- Используй lucide-react для иконок, если нет кастомной иконки.
- Если пользователь просит настроить `hover`, также добавляй `cursor-pointer`, если элемент не disabled.
- Перед изменением отступов и размеров по визуальному комментарию определи конкретные элементы или края, между которыми их нужно менять, сверяясь с выделенным контейнером и скриншотом. Если на экране есть несколько подходящих отступов и цель нельзя надёжно определить, задай короткий уточняющий вопрос до правки.
