# Инструкции по проекту

Это high-fidelity прототип, а не production.

Когда ссылаешься на локальные документационные файлы, по возможности указывай и файл, и название нужной секции. Номера строк необязательны и должны восприниматься только как примерный ориентир, а не как основной способ навигации.

Обращайся к пользователю на "ты".

Отвечай коротко: сначала главный вывод, потом 3–5 пунктов максимум. Без длинных объяснений, если пользователь не просит.

В работе над инструкциями не пиши финальный текст инструкции целиком, пока пользователь не попросит. Сначала предлагай структуру и 2–3 ключевых правила.

Диапазоны, интервалы и иные промежутки отделяй знаком `–`, а не знаком `-`. Пример: `10–20`, `май–июнь`, `стр. 5–7`.

Используй существующие компоненты из `src/components/ui`, прежде чем создавать новый UI.

Не воссоздавай Figma-слои буквально.
Не генерируй слишком глубоко вложенную div-структуру.
Предпочитай семантический HTML.

Используй дизайн-систему RHOOD как источник стилей: существующие компоненты из `src/components/ui` и токены из `src/styles/design-tokens.css`.
Не добавляй новые стили, цвета, размеры или радиусы через Tailwind, если для них уже есть токен или компонент RHOOD. Tailwind допускается только для компоновки и в случаях, когда в RHOOD нет подходящего решения.
Используй shadcn/ui только как техническую основу, не заменяя им компоненты и стили RHOOD.
Используй lucide-react для иконок, если нет кастомной иконки.

- Если пользователь просит настроить `hover`, также добавляй `cursor-pointer`, если элемент не disabled.
